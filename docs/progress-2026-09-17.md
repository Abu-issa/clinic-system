## Pre-commit hardening gate — File Storage Phase 1 (2026-09-17)

Focused re-review before commit; implementation preserved, no redesign:

1. Reparse-point/junction safety: confirmed exploitable — a directory junction planted at
   `<root>\clinic-files` passed prefix containment and would redirect keys outside the root.
   Fix in `LocalFileStorage`: every existing path component below the root is refused if it
   carries the Windows ReparsePoint attribute (all five operations, checked per resolve).
   Regression test creates a real junction and proves refusal with nothing written to the
   target. Root-itself trust assumption documented (operator-controlled; the application can
   never create reparse points — only fixed dirs and hex-named files).
2. Cancellation: new test proves mid-stream OperationCanceledException propagates with
   original semantics, cleans staged bytes, persists no metadata (input-stream failure cleanup
   was already tested).
3. Compensation: reconfirmed (stage→promote→save-fail ⇒ object deleted, no row); new test
   proves a failing compensating delete never masks the primary metadata failure and the
   resulting orphan object (no dangling metadata) matches the documented behavior.
4. Collision: new test proves promote never overwrites (controlled IOException, existing bytes
   untouched, no metadata persisted, staged object cleaned); no retry complexity added.
5. Configuration recheck: wwwroot/production validations confirmed; no credentials anywhere;
   tests use only unique temp storage roots.
6. Latent bug caught by the new tests: staged cleanup validated staging keys against the
   final-key shape, so the service's staged cleanup silently no-op'd (swallowed
   ArgumentException). DeleteAsync now validates each key against its own prefix; the
   PromoteAsync contract comment was corrected to state that a failed promotion leaves the
   staged object for caller cleanup. All prior tests still pass unchanged.

Verification: build 0 warnings/0 errors; unit 197 passed (4 new hardening tests); full suite
561 passed, 0 failed/skipped; EF has-pending-model-changes clean; git diff --check clean;
migration `20260916214417_AddFileStorageFoundation` re-verified additive (StoredFiles +
3 indexes only) and still NOT applied; ClinicDb untouched; nothing committed or pushed.
