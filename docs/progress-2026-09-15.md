from IdentityDbContext while preserving the medical mappings and IUnitOfWork behavior. Identity

permissions or MFA claim and is never used by medical endpoint authorization. Enrollment and

amr=mfa and persisted grants. Both schemes check revocation on every authenticated request.

or browser storage token path exists. Five failures trigger 15-minute Identity lockout. The auth
routes share a bounded fixed-window rate limiter. Logout revokes all account sessions.

The explicit local command provisions only the first responsible Doctor with existing Doctor IDs
and scopes, and is safe to rerun without resetting credentials or grants. Local administrative

1. High integrity risk: a current-version empty/partial clinical snapshot superseded unseen and

   explicit JSON presence. Optional values can still be intentionally null; missing fields return 400.

   login. Supported set-grants still rotates stamps and clears challenges.
4. High privacy risk: EF SaveChangesFailed diagnostics included the duplicate MRN in SQL exception

   an ILogger sink capturing both formatted state and exception text. The API suppresses

   unexpected failures retain the sanitized exception-type/trace-ID API handler.

## Pre-commit correctness review — Medication Catalog and Prescriptions Phase 1

Confirmed and fixed one high-severity defect: the replacement uniqueness backstop was directed
wrong. The unique filtered index sat on ReplacedByPrescriptionId, which only prevents two
originals claiming the same replacement; it did not prevent two prescriptions both referencing
the same original via ReplacesPrescriptionId. The mapping, migration, designer and snapshot now
carry correctly directed filtered unique indexes on BOTH link directions:
- IX_Prescriptions_ReplacesPrescriptionId (unique, IS NOT NULL): at most one replacement per
  original — the authoritative database backstop for direct/future writers.
- IX_Prescriptions_ReplacedByPrescriptionId (unique, IS NOT NULL): at most one original per
