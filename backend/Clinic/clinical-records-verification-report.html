Architecture Decision: Doctor Clinical Authority Model

Explicit Association Rule Enforced

A staff user in the Doctor role may create, edit, finalize, or amend a Visit ONLY when Visit.DoctorId == StaffUser.AssociatedDoctorId, verified directly against the current persisted database state per request.

Enforced Architectural Rules

  • No Scope Reinterpretation: Neither schedule_doctor_id nor appointment_doctor_id grants clinical authority over Visits.
  • Persisted State Validation: AssociatedDoctorId is resolved from the live database context via UserManager<StaffUser>, preventing stale cookie escalation.
  • No Cross-Doctor Delegation: Doctors cannot mutate visits owned by other physicians in this slice.
  • Role Isolation: DoctorAssistants are restricted to vitals.write and visits.read; Receptionists are strictly excluded from all clinical endpoints (403 Forbidden).

Detailed Concurrency & Race Condition Architecture

The clinical record subsystem uses a strict optimistic concurrency control scheme implemented at the aggregate root level:

// Optimistic Concurrency Token Verification in VisitStore.cs
public async Task<VisitResult> UpdateAsync(Guid patientId, Guid visitId, UpdateVisitRequest request, string actorStaffId, CancellationToken ct)
{
    var visit = await db.Set<Visit>()
        .Include(v => v.VitalMeasurements)
        .Include(v => v.Amendments)
        .SingleOrDefaultAsync(v => v.Id == visitId && v.PatientId == patientId, ct);

    if (visit is null) return VisitResult.Failure(VisitError.VisitNotFound);
    if (!visit.RowVersion.SequenceEqual(request.ExpectedRowVersion))
        return VisitResult.Failure(VisitError.VisitChanged);

    visit.UpdateClinicalContent(request.Content, clock.GetUtcNow());

    try
    {
        await db.SaveChangesAsync(ct);
        return VisitResult.Success(Map(visit));
    }
    catch (DbUpdateConcurrencyException)
    {
        return VisitResult.Failure(VisitError.VisitChanged);
    }
}
